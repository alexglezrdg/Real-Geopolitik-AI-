  2. src/scheduler.ts
     - Cron scheduler (hourly/daily)
     - Calls: runOnce() in loop
     - Environment-driven (SCHEDULER_ENABLED, SCHEDULE_CRON)

DATA SOURCES:
  3. src/rss.ts
     - Fetches from 25+ RSS sources (news_sources.ts)
     - Returns: FeedItem[] with title, url, snippet, source, publishedAt

  4. src/news_source_gdelt.ts
     - GDELT API client (geopolitical event database)
     - Status: Partially broken (content-type issues)

FILTERING & SELECTION:
  5. src/news_picker.ts
     - scoreStory() → scores by geopolitics keywords + region priority
     - pickTopStories() → returns ranked candidates
     - detectUrgencyTag() → ÚLTIMA HORA / CLAVE / EN DESARROLLO

  6. src/geo_gate.ts
     - geoGate() → allows/blocks by region + hard keywords
     - STATUS: ENFORCED in pickFirstNotDuplicate()

DEDUPLICATION (4-LAYER):
  7. src/dedupe_store.ts
     - Layer 1: DUP_URL (canonical_url match)
     - Layer 2: DUP_FP (strong fingerprint)
     - Layer 3: DUP_NEAR (simhash Hamming ≤3)
     - Layer 4: DUP_TOPIC (topic_hash with stopwords)
     - TTL: 14 days (configurable)
     - Database: SQLite dedupe_entries table

  8. src/url_resolver.ts
     - resolveFinalUrl() → follows redirects
     - resolveFinalUrlWithGoogleNews() → handles Google News RSS
     - normalizeUrl() → removes tracking params
     - Timeout: 3000ms

GENERATION:
  9. src/claude.ts
     - generateThreadWithClaude() → LLM-based thread generation
     - Max 3 tweets per thread
     - Calls OpenAI/Claude API
     - TOKEN COST: ~2000 tokens per post

  10. src/curator-llm.ts
      - refineCandidatesWithLLM() → LLM-based filtering
      - STATUS: SECONDARY (used by some paths)

  11. src/run_once.ts (buildTemplateThreadNewsPack)
      - Deterministic template (no LLM call)
      - TOKEN COST: ~100 tokens per post
      - Used when score < LLM_SCORE_THRESHOLD (default 85)

FORMATTING:
  12. src/run_once.ts (buildFinalTweetText, stripUrlsAndMoreDetails)
      - Ensures single URL: "Más detalles: {url}"
      - Removes duplicates via stripUrlsAndMoreDetails()

  13. src/post_writer_maestro.ts
      - MaestroInput → formatted tweet
      - STATUS: USED for some paths

IMAGE GENERATION:
  14. src/openai_image.ts
      - generateNewsImage() → DALL-E image generation
      - Requires IMAGE_LIVE=1
      - TOKEN COST: ~$0.02-0.10 per image

  15. src/image_composer.ts
      - Compose images with portraits, overlays
      - STATUS: ADVANCED (optional)

  16. src/image_mode.ts
      - Decides when to use image
      - decideImageMode() → HYBRID/PORTRAIT/NONE

POSTING:
  17. src/x.ts
      - postThread() → posts to X/Twitter
      - Requires X_API_KEY, X_API_SECRET
      - Returns: tweetIds[]

STORAGE:
  18. src/db.ts
      - SQLite database (data/bot.sqlite)
      - Tables: posts, dedupe_entries, curated_stories
      - Functions: isAlreadyPosted(), markPosted(), getTodayPostCount()

  19. src/post_history.ts
      - canonicalizeUrl() → URL normalization
      - recordPosted() → marks post in history
      - hasRecentDuplicate() → checks 48h TTL

PROCESS LOCK (Anti-parallel):
  20. src/process_lock.ts
      - .runlock file mechanism
      - PID + stale detection (>30min)
      - Prevents simultaneous execution

B) PROBLEMAS DETECTADOS
================================================================================

P0 (CRITICAL - ROMPE FUNCTIONALITY):
────────────────────────────────────────────

P0-1: TOPIC COOLDOWN NOT IMPLEMENTED
  Evidence: src/dedupe_store.ts has topic_hash layer, but NO cooldown tracking
  Impact: Same story (e.g., "bloqueo naval Cuba") can be posted multiple times in <72h if URL changes slightly
  Solution: Add topic_cooldown table + check before posting
  Severity: HIGH (user complaint: "same story repeated")

P0-2: stripUrlsAndMoreDetails NOT RE-INJECTING URL
  Evidence: src/run_once.ts line 133-142
  Problem: Function strips ALL URLs but buildFinalTweetText() is called AFTER generation
  Current: cleanText → suffix injected → but no guarantee final URL is there
  Risk: Tweet might have 0 URLs or >1 URL in some edge cases
  Solution: Guarantee single URL injection after all generation done

P0-3: GDELT SOURCE BROKEN
  Evidence: Live run showed "unexpected content-type: text/html"
  Impact: No geopolitical signal from GDELT (25% of expected sources)
  Solution: Fix URL or remove from active sources

────────────────────────────────────────────

P1 (HIGH - WASTE/INEFFICIENCY):
────────────────────────────────────────────

P1-1: CURATOR-LLM REDUNDANCY
  Evidence: src/curator-llm.ts + src/curator.ts both exist
  Problem: refineCandidatesWithLLM() is NOT used in run_once.ts flow
  Impact: Dead code, confusing maintenance
  Solution: Remove curator-llm or integrate properly

P1-2: LLM CALLED EVEN FOR LOW SIGNAL
  Evidence: src/run_once.ts line 597
  Current: Check is "if (useLLM)" but fallback buildTemplate is only used if score <85
  Problem: If score=87 but low-signal geopolitics, still calls expensive LLM
  Solution: Add SECOND check for hard-geo-gate before LLM call

P1-3: NO CACHING FOR REPEATED STORIES
  Evidence: src/run_once.ts line 597+
  Problem: If same story appears in RSS feed multiple times (common), still generates new tweet each run
  Solution: Cache generated threads by topic_hash + reuse if within 72h

P1-4: MULTIPLE POST HISTORY CHECKS
  Evidence: src/run_once.ts line 175 (hasRecentDuplicate) + line 184 (dedupeCheck)
  Problem: Two similar dedup checks, first is 48h TTL, second is 14d
  Redundancy: Can consolidate
  Solution: Merge into single consistent dedup call

  Evidence: src/run_once.ts logs with console.log (no structured format)
  Impact: Hard to parse and monitor
  Solution: Add JSON logging with reason codes (DUP_URL, DUP_TOPIC_COOLDOWN, etc.)
